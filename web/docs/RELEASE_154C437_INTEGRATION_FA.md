# اتصال و تحویل محصول ماکان — ۲ نوامبر ۲۰۲۶

مرجع اجرای کلاینت، برنامهٔ `web/` و سرور `http://94.184.32.84:8090` است. Swagger و OpenAPI زنده بررسی شدند. PDF ارسالی با نام `MakanApp-Frontend-Backend-154c437-FA.pdf` قواعد دامنه را توضیح می‌دهد؛ قرارداد transport از OpenAPI همان سرور گرفته شده است. شمارهٔ commit مستند `154c4372e8c03469f678a417caf79d58a51333df` است؛ شناسهٔ دقیق binary مستقر از سمت سرور در دسترس نیست و تأیید نشده است.

## تغییر قرارداد و اتصال

قرارداد قبلی ۳۲۷ مسیر و قرارداد فعلی ۳۴۲ مسیر دارد. ۱۵ مسیر اضافه و هیچ مسیر قبلی حذف نشده است. SDK محدود کلاینت اکنون ۲۳۶ عملیات و ۴۴۱ schema دارد. مسیر مدیریت کتابخانهٔ `/api/admin/v1/library/sources` به کلاینت وارد نشده است. دریافت binary منبع از BFF اختصاصی عبور می‌کند.

مرورگر به همان origin کلاینت درخواست می‌دهد. BFF، نشست و توکن را سمت سرور نگه می‌دارد و درخواست را به backend ارسال می‌کند. فرم‌ها از قرارداد تولیدشده اعتبارسنجی می‌شوند. `X-Makan-Context`، لغو درخواست و بررسی revision از نمایش پاسخ یک حساب/فضا در حساب/فضای بعدی جلوگیری می‌کنند. کلید نشست، کوکی و اطلاعات ورود در شواهد ذخیره نشده‌اند.

| بخش | رفتار قابل استفاده در محصول |

## راهنمای استفاده

۱. از ورود، حساب و فضای مجاز را انتخاب کنید. فهرست پیام‌های حساب از سرور دریافت می‌شود و برای دیدن پیام شخصی به تغییر فضای آموزشی نیازی نیست.

۲. پروفایل، مسیر «منابع آموزشی» را باز می‌کند؛ نشانی مستقیم `/personal/resources` است. فضای شخصی، کلاس، آموزشگاه یا کتابخانه را از گزینه‌های مجاز انتخاب کنید. برای فضای کلاس ابتدا کلاس را انتخاب کنید.

۳. برای ایجاد منبع، عنوان، فایل و دلیل ثبت را وارد کنید. بارگذاری فایل و ایجاد منبع دو عملیات‌اند. فایل Pending ابتدا دوباره بررسی می‌شود؛ Ready به معنی آماده‌بودن AI نیست. اگر نتیجهٔ ثبت نامعلوم باشد، «پیگیری ثبت منبع» همان شناسه و payload را تکرار می‌کند؛ درخواست ایجاد در sessionStorage وابسته به حساب و revision حفظ می‌شود.

۴. جزئیات منبع وضعیت فایل، منبع و AI را جدا نشان می‌دهد. برای تغییر، دلیل وارد کنید. ابتدا پیش‌نویس را ذخیره و سپس انتشار را تأیید کنید. تعارض 412 نوشتهٔ شما را پاک نمی‌کند؛ نسخهٔ تازه را بازبینی و «ادامهٔ ویرایش با نسخهٔ جدید» را انتخاب کنید. رد قطعی اعتبارسنجی، متن و فایل آماده را حفظ و فرم ایجاد را برای اصلاح باز می‌کند؛ خطای مبهم همچنان همان فرمان را پیگیری می‌کند. نسخهٔ جدید پس از تعارض، بازبینی و تأیید صریحِ ادامه می‌خواهد. revision عددی با token رشته‌ای version متفاوت است.

۵. در تب منابع دستیار، منابع واقعی را انتخاب و دسترسی را بررسی کنید. خروجی preflight دربارهٔ مجوز و امکان بازیابی است. بخش نمونهٔ دستیار همچنان صریحاً نمونه است؛ تولید واقعی AI در این مرحله فعال نشده است.

۶. ویرایش گروه/کانال فقط کنترل‌های مجاز را نشان می‌دهد. تغییر عکس، نام، تنظیمات، مدیران و دعوت مجوزهای مستقل دارند. «راهنمای مجوزهای گفتگو» شرح‌های جاری سرور را نمایش می‌دهد؛ به‌تنهایی مجوزی تغییر نمی‌دهد.

## قواعد دسترسی

- سن، تاریخ تولد، verificationStatus و effectiveAgeCategory مجوز پیام‌رسانی ایجاد یا لغو نمی‌کنند. `MessagingStatus.allowedActions` و capability سرور مرجع‌اند. نقص پروفایل لازم یا محدودیت معتبر سرور همچنان رعایت می‌شود.
- منابع Personal به مالک تعلق دارند و upload آن‌ها حتی از فضای آموزشی با scope صریح Personal انجام می‌شود. workspace کاربر برای این کار تغییر نمی‌کند.
- برای منابع Class، دانشجو محتوای منتشرشدهٔ کلاس مجاز را می‌خواند؛ نوشتن معلم/مدیر و انتساب کلاس در سرور کنترل می‌شود. منابع Organization با مجوز مدیر نوشته می‌شوند. والد به‌صورت خودکار دسترسی کلاس یا نوشتن نمی‌گیرد.
- کتابخانه فقط metadata منابع عمومی منتشرشده را نشان می‌دهد؛ upload مدیریتی، فایل و استفاده در AI وارد این کلاینت نشده‌اند.
- downloadUrl پاسخ، جایگزین مجوز Files یا Sources نیست. فایلِ متعلق به uploader دیگر از مسیر upload receipt پذیرفته نمی‌شود.
- در فضای رسمی، دسترسی آموزشی و effectiveCapabilities مرجع‌اند؛ نبودن عنوان Owner/Admin در roster مانع دسترسی مؤثر معتبر نیست. GET، repair یا provisioning ایجاد نمی‌کند.

## روش آزمون و شواهد

۳۰۱ آزمون واحد در ۵۳ فایل موفق‌اند. شمارش نهایی مرورگر و نتایج ماشینی در `docs/quality/RELEASE_154C437_CHECKS.json` و رسیدهای جداگانهٔ همان پوشه ثبت می‌شوند. گزارش PDF از همین شواهد تولید می‌شود.

| لایه | دامنهٔ اثبات |
| --- | --- |
| زنده، خواندن مستقیم | پنج نوع حساب Student، Teacher، Parent، Manager و Personal؛ OTP نشست تست، me، workspace، messaging status، account inbox، permission catalog، replay، منابع و مسیرهای آموزشی مجاز |
| زنده، BFF و مرورگر | ورود از BFF، اعتبارسنجی پاسخ با قرارداد کلاینت، منابع شخصی/کتابخانه، صندوق، صفحهٔ محصول و حفظ فضای انتخاب‌شده |
| واحد و امنیت | سیاست capability، ترتیب سرور، cursor و resync، binding منبع و فایل، جلوگیری از دریافت Library، MIME، Origin و تغییر نشست در انتقال |

در بررسی گروهی BFF، ورود دو حساب پاسخ 503 داشت. هر پنج نقش در بررسی موفقِ گروهی یا بازبررسی جداگانه تأیید شدند؛ خطاهای اولیه حفظ شده‌اند و علت قطعی آن‌ها از این شواهد تعیین نشده است. آزمون زنده هیچ پیام، دعوت، منبع، فایل، سفارش یا پرداختی ایجاد نکرد. تنها نشست‌های اختصاصی آزمون وارد/انتخاب/خارج شدند. تمام نوشتن‌های دامنه در سناریوهای خودکار روی fixture محلی انجام شده‌اند؛ موفقیت آن‌ها اثبات اجرای mutation، تراکنش DB، ایمنی یا ACL سرور واقعی نیست. اعداد آزمون‌های بک‌اند در PDF ورودی، نتایج اجرای ما محسوب نمی‌شوند.

### بازتولید

فرمان‌ها داخل `web/` اجرا می‌شوند. Node حداقل ۲۲ و وابستگی‌های lockfile لازم‌اند. env موجود را بازنویسی نکنید.

```bash
npm ci
npm run api:generate
npm run generated:check
npm run typecheck
npm run lint
npm test
npm run format:check
npm run build -- --webpack
PLAYWRIGHT_CHANNEL=chrome npm run test:browser -- tests/browser/release-154c437.spec.ts
node scripts/verify-release-browser.mjs 1
node scripts/verify-release-browser.mjs 2
node scripts/verify-release-browser.mjs 3
```

در نبود Chrome، مرورگر Playwright را نصب و channel متناسب انتخاب کنید. runner سه‌بخشی فعلی Chrome را انتخاب می‌کند. پورت‌های ۳۱۳۲ و ۳۴۵۷ باید آزاد باشند؛ fixture اجازهٔ اتصال خارجی ندارد. فایل‌های `test-results` برای trace و screenshot خطا مناسب‌اند و گزارش‌های خلاصهٔ قابل تحویل در `docs/quality` قرار دارند.

خواندن زنده opt-in محلی دارد، در CI اجرا نمی‌شود و فقط حساب‌های تست موجود را استفاده می‌کند. اطلاعات ورود و OTP را داخل گزارش عمومی نگذارید:

```bash
MAKAN_TEST_READ_SMOKE=1 node scripts/verify-release-154c437.mjs
# نیازمند preview محلی متصل به backend واقعی روی پورت 3133:
MAKAN_TEST_READ_SMOKE=1 node scripts/verify-release-154c437-bff.mjs
```

برای اجرای عادی، `BACKEND_BASE_URL=http://94.184.32.84:8090`، `APP_ORIGIN` دقیق و `SESSION_SECRET` تصادفی ۳۲بایتی لازم‌اند. HTTPS و Cookie Secure برای محیط عمومی بر اساس دامنهٔ استقرار تنظیم شوند. فایل env و session volume موجود حفظ شوند.

## محدودیت‌ها و ادامهٔ کار

- اتصال و آزمون‌های این تحویل، اجرای محلی کلاینت علیه سرور معرفی‌شده است. استقرار سرور عمومی یا تغییر backend انجام نشده؛ Docker daemon و فایل env استقرار در این محیط حاضر نیستند.
- OCR، extraction، embedding، vector، RAG و اجرای واقعی AI طبق سند هنوز مرحلهٔ فعال‌سازی سرورند. UI فقط preflight عملیات Chat را اجرا می‌کند؛ سه عملیات source-aware دیگر به جریان تولیدی دستیار وصل نشده‌اند.
- پذیرش دعوت توسط حساب مخاطب، اجرای cron انقضا، backfill اعلان‌های تاریخی، fault tolerance سرور و آزمون بار واقعی در این مرحله اجرا نشده‌اند. انقضای هفت‌روزه در کلاینت محاسبه نمی‌شود.
- ویرایش جزئی permission bitها و delegation مدیریتی در UI اضافه نشده است؛ کاتالوگ فقط خواندنی است. قابلیت‌های تماس، پخش زنده، پیام خوشامد و واکنش سراسری که سرور قرارداد کامل آن‌ها را ندارد همچنان روشن اعلام می‌شوند.
- نسخهٔ جدید منبع expectedVersion دارد و تکرار مبهم در همان فرم token قبلی را نگه می‌دارد. پیش‌نویس ایجاد منبع پس از reload بازیابی می‌شود؛ نگهداری فایل انتخابیِ ثبت‌نشده یا عملیات نسخهٔ جدید پس از بستن صفحه تضمین نشده است.
- commerce موجود حفظ شده؛ پرداخت واقعی، callback یا مصرف AI/اعتبار در این تحویل اجرا نشده است. entitlement و محدودیت سرور دور زده نمی‌شود.
