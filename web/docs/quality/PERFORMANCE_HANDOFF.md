# تحویل بهینه‌سازی سرعت ماکان

## اصلاح‌های انجام‌شده

۱. BFF درخواست‌های GET مستقل را با read gate موجود هم‌زمان اجرا می‌کند. تغییر نقش/فرزند، ویرایش، خروج و تمدید credentials همچنان قفل اختصاصی و اولویت writer دارند. getClientState فقط promise بررسیِ در حال اجرای همان نشست را به خوانندگان هم‌زمان می‌دهد؛ بعد از پایان یا خطا هیچ نتیجه‌ای نگه نمی‌دارد. اعتبار هویت و context، revision، allowlist، DTO و مجوز backend حفظ شدند. کاربر/سازمان قبلی با cache عمومی یا TTL معتبر فرض نمی‌شود.

۲. هویت و فضای فعال در حالت shared هم‌زمان خوانده می‌شوند. نیاز به refresh یا نوشتن signature به مسیر اختصاصی ارتقا می‌یابد؛ در آن مسیر خواندن‌های وابسته به credentials سری هستند. requireClientPage نیز برای خواندن صرف فایل نشست پشت سایر GETها قفل اختصاصی نمی‌گیرد.

۳. بارگیری کد فرم‌ها، ارزیابی، آزمون، جزئیات کلاس و بخش‌های مدیریت در orchestrator آموزشگاه مرحله‌ای شد. LoadingSkeleton موجود باقی است و componentهای dynamic در سطح ماژول تعریف شده‌اند؛ طراحی، مسیرها، نقش و حفظ پیش‌نویس تغییر نکردند. PWA promotion و وابستگی‌های گفت‌وگوی راهنمای نصب در صفحات عمومی/نامناسب بارگیری نمی‌شوند و کلید بستن پیشنهاد قبلی حفظ است.

۴. تست کامل یک وابستگی ناخواسته به ترتیب CSS پیدا کرد. اولویت min-height پاسخ‌نامه در workspace خودش اصلاح شد تا CSS فرم عمومی که دیرتر می‌رسد، کادر پاسخ را کوچک نکند. قواعد typography موبایل دست‌نخورده‌اند. تست موجود همچنان ارتفاع۲۶۰/۲۹۰/۳۲۰ و حفظ متن در resize را الزام می‌کند.

## روش سنجش

tests/browser/performance.spec.ts با backend fixture محلی اجرا می‌شود؛ شبکهٔ خارجی در مرورگر ممنوع است. ورود سرد و صفحهٔ آموزشگاه Student، تعداد/حجم decoded فایل‌های JavaScript، TTFB و FCP نمونه ثبت می‌شوند. حجم decoded، حجم gzip یا کل دانلود صفحه نیست. سه GET مخاطبین، دعوت‌ها و snapshot هر کدام۳۰۰میلی‌ثانیه تأخیر یکسان می‌گیرند؛ زمان batch و شمار me/current ثبت می‌شود. تست روی زمان مطلق یا امتیاز Lighthouse assertion ندارد تا به سرعت دستگاه CI وابسته نشود؛ correctness هم‌زمانی با deferred promise و تست واحد بررسی می‌شود.

مبنای قبل: PERFORMANCE_before.json روی نسخهٔ پیش از اصلاح. اجرای همان تست در مجموعهٔ کامل در PERFORMANCE_after.json است؛ نمونهٔ مستقل نهایی پس از پایان quality ثبت می‌شود. این اعداد تضمین سرعت همهٔ کاربران یا اثبات اجرای سرویس‌های واقعی نیستند. برای اندازه‌گیری جدید پس از build از ریشهٔ web:

```powershell
$env:MAKAN_PERFORMANCE_TAG = 'latest'
npx playwright test tests/browser/performance.spec.ts
```

آدرس‌ها و داده‌ها fixture هستند؛ تست پیام یا پرداخت واقعی ایجاد نمی‌کند. tag قبل برای مبنای تاریخی است و نباید با اجرای نسخهٔ جدید بازنویسی شود.

## خواندن واقعی سرور تست

PERFORMANCE_LIVE_READS.json بررسی دستیِ opt-in چهار حساب مصنوعی مجاز را ثبت می‌کند. فقط نشست خودش ایجاد/انتخاب/خارج شده و عملیات دامنه GET است؛ token، phone و شناسهٔ اشخاص در گزارش نیست. نمونه‌های workspace/current، contacts و inbox پاسخ۴۵تا۷۰میلی‌ثانیه داشتند؛ هر چهار context ثابت ماندند. این اندازه‌گیری با زمان مصنوعی benchmark یا آزمون ارسال واقعی پیام یکی نیست. lookup404 و Missing رسمی قبلی طبق G19 جدا هستند.

## نتیجهٔ نهایی

`npm run quality` نهایی exit=0: format، lint با۱۸۵مرز/بدون چرخه، typecheck،۲۳۴تست واحد در۴۶فایل، generated:check، build و۹۵تست مرورگر موفق؛ صفرشکست/skip/flaky. لاگ PERFORMANCE_QUALITY.log و JSON کامل PERFORMANCE_BROWSER.json محفوظ‌اند. دو اجرای مستقلِ تک‌تست نیز موفق بودند و به شمارش۹۵ اضافه نشده‌اند. نخستین اجرای مرورگر۹۴موفق/۱شکستِ CSS داشت؛ لاگ/JSON اولیه محفوظ‌اند. هیچ assertion، retry یا تستی برای پنهان‌کردن خطا حذف/ضعیف/skip نشد.
