# تحویل اعضا، پرونده و اجرای یکپارچهٔ کلاینت — ۳۰ اکتبر ۲۰۲۶

## تغییرهای قابل استفاده

- اعضای آموزشگاه: دو مقصد اعضا/پرونده، انتخاب نقش، وضعیت عضویت، جستجو و صفحه‌بندی سمت سرور، جدول دسکتاپ و کارت موبایل، اقدام توپر مشاهدهٔ پرونده و نمایش نام کاربری بلند بدون سرریز.
- پرونده: هویت و اتصال حساب، مشخصات در گروه‌های خوانا، شناسه‌ها در بخش بازشونده و فرم مستقل تکمیل/بازبینی. canEditNames سرور ملاک نمایش ویرایش است؛ دسترسی مستقیم به ویرایش غیرمجاز هم بررسی می‌شود. خطای ذخیره، متن و پیش‌نویس را پاک نمی‌کند.
- مرز مسئولیت: directory-view برای اجزای مشترک، member-directory برای عضویت‌ها، person-records برای پرونده و فرم، people.module.css برای ظاهر؛ manager و creation-pages مسیرهای قبلی را با export سازگار حفظ می‌کنند.
- نشست Docker از preview با نام کوکی مستقل جداست؛ مرورگر کوکی را به پورت محدود نمی‌کند. migration سرویس‌ورکر فقط cacheهای شناخته‌شدهٔ قدیمی را کنار می‌گذارد؛ IndexedDB، outbox و پیش‌نویس حذف نمی‌شوند.

## بررسی‌های اجراشده

`npm run quality` موفق: format، lint، typecheck، generated:check، build، **۲۱۴تست واحد در۴۱فایل** و **۷۹تست مرورگر**؛ صفر شکست/skip/flaky در اجرای نهایی. lint،۱۷۴مرز ماژول و نبود چرخه را بررسی کرد. SDK موجود۲۰۰عملیات/۳۷۷schema است؛ endpoint مالک تولید نشد.

تست‌های تازه: فیلترهای واقعی درخواست و جستجو، نبود لینک پروندهٔ جعلی، حالت فقط‌خواندنی و ورود مستقیم غیرمجاز، خطای۵۰۳ پایدار و retry دستی، نگهداری فرم ناموفق، ساخت با پاسخ معتبر، اندازه‌های۳۹۰/۸۳۴/۱۴۴۰، نام کاربری بلند و اقدام قابل لمس. تست واحد کوکی مستقل و migration cache نیز اضافه شد. تست محلی اولیه۱۳موفق/۱شکست داشت: انتظار خطا با بازخوانی مجاز هم‌زمان بود؛ fixture خطا تا retry صریح پایدار شد و assertion حذف نشد. شمارش اجرای اولیه به شمارش نهایی اضافه نمی‌شود.

شواهد: MEMBERS_DOCKER_QUALITY.log، MEMBERS_BROWSER.json و۱۲تصویر output/review/member-directory. تصاویر منتخب اعضا، پرونده و فرم دیده شدند. preview3130 پس از به‌روزرسانی /enter را با۲۰۰ پاسخ داد و نشست‌های خصوصی آن حفظ شدند.

## بازنشستگی نسخهٔ قدیمی

علت ظاهر قدیمی8080، کانتینر مستقل makanapplication-web-1 با nginx/Vite بود؛ build نسخهٔ Next روی3130، آن را عوض نمی‌کرد. ریشه اکنون فقط راه‌انداز Next درweb است و root Compose همان web/compose.yaml را include می‌کند. package/README/AGENTS و نمونهٔ env ریشه با این وضعیت هماهنگ شدند؛ CI علاوه بر quality، build واقعی Docker را نیز اجرا خواهد کرد. اجرای CI میزبانی‌شده در این تحویل مشاهده نشده است.

سورس و خروجی قدیمی پیش از کنارگذاشتن با CRC و SHA256 بررسی و خارج از پروژه آرشیو شدند: Makan-Legacy-Archive-20261030-144511.zip و آرشیو تکمیلی tests در Desktop. پوشهٔ خام .files نیز خارج از پروژه باقی است تا بازیابی ممکن باشد؛ node_modules قدیمی هم از پروژه فعال خارج شد. ادعای آزادشدن کامل فضای دیسک نداریم. فهرست و hashها در LEGACY_RETIREMENT_MANIFEST.json است. Git بازنویسی نشد. .freebuff، packages/toolkit و malikam_excel.json به‌دلیل کاربرد نامشخص حفظ شدند. نشست‌ها، فایل‌های محرمانه و volumeها پاک نشدند.

## Docker

build نهایی و اجرای Docker موفق شد و makan-client-web-1 روی127.0.0.1:8080 سالم است. ورود۲۰۰، نشست ناشناس۴۰۱، کنترل مبدأ۴۰۳ و کوکی مستقل بررسی شدند. از داخل کانتینر، OpenAPI واقعی۲۰۰ و۳۲۲مسیر داشت. کانتینر قدیمی و image83618194fd34 حذف شدند؛ پنل مالک سالم است. جزئیات در docker.md و MEMBERS_DOCKER.json هستند. build اولیه به‌دلیل نبود design/tokens.json در allowlist شکست خورد؛ فقط همان ورودی ضروری به context اضافه شد. توقف اولیهٔ موتور Docker/WSL با مجوز صریح کاربر برای restart پیگیری شد؛ factory reset یا حذف داده انجام نشد. ورود و عملیات نوشتن بک‌اند روی Docker هنوز جداگانه بررسی نشده‌اند.
