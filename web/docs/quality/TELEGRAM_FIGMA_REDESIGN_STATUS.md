# وضعیت بازطراحی پیام‌رسان با مرجع Telegram

**به‌روزرسانی ۱ نوامبر:** کاربر PDF کامل مرجع را ارائه کرد؛ مانع دریافت تصویر برای توسعهٔ بصری رفع و پیاده‌سازی آغاز شد. این فایل سابقهٔ بررسی اولیه است. وضعیت جاری و نگاشت صفحه‌ها در [گزارش پیاده‌سازی PDF](TELEGRAM_PDF_IMPLEMENTATION.md) نگهداری می‌شود.

تاریخ بررسی: ۲۰۲۶-۱۱-۰۱

## خواستهٔ کاربر و مرجع

کاربر بازطراحی بخش پیام‌رسان مطابق فایل مشخص Telegram UI Screens را خواسته است. این مرجع جایگزین تصمیم بصری قبلی پیام‌رسان است؛ دامنهٔ نقش‌ها، مجوزها و اتصال سرویس با تغییر ظاهر عوض نمی‌شود.

- فایل: https://www.figma.com/design/vbjYyH7wGplJq9sAYM5pB8/Telegram-UI-Screens--Community-?node-id=0-3506
- Community: https://www.figma.com/community/file/874574404452104362/telegram-ui-screens
- کلید فایل: `vbjYyH7wGplJq9sAYM5pB8`؛ صفحهٔ خواسته‌شده: `0:3506`، Telegram.
- نشست ابزار Figma: `61b29bb7-287e-428a-ae40-8a61a2ebd9e4`.

## شواهد دریافت‌شده و مانع

متادیتای صفحه دریافت شد و عنوان‌های Classic Theme و Dark Theme و قاب Telegram Chats با شناسهٔ `0:3515` و اندازهٔ ۳۷۵×۸۱۲ در آن وجود داشتند. درخواست اولیهٔ design context برای خود canvas پیام «nothing selected» داد. هنگام دریافت context قاب مشخص، ابزار Figma اعلام کرد سهمیهٔ MCP پلن Starter تمام شده است. تصویر render و context کامل اجزای این قاب دریافت نشدند. دسترسی وب عمومی نیز صفحهٔ Design را باز نکرد و Community با robots محدود بود؛ این نتیجه به معنی حذف فایل یا نداشتن دسترسی حساب کاربر نیست.

بنابراین رنگ‌ها، فاصله‌ها، دارایی‌ها و تطابق پیکسلی با مرجع هنوز بررسی نشده‌اند. متادیتای درخت لایه‌ها جای تصویر و مشخصات طراحی را نمی‌گیرد. هیچ تغییر بصری حدسی به برنامه اعمال نشد.

ورودی لازم برای ادامه: بازیابی دسترسی ابزار Figma یا خروجی قابل مشاهدهٔ صفحه‌های مرجع، مانند PDF/تصاویر با وضوح اصلی؛ همراه فایل `.fig` در صورت امکان برای حفظ ساختار و مشخصات. تصاویر باید حداقل فهرست گفتگو، چت، منوی گفتگو و پیوست را در حالت‌های روشن و تاریک پوشش دهند. فرستادن دوبارهٔ همین لینک به‌تنهایی محدودیت سهمیه را برطرف نمی‌کند.

## وضعیت واقعی کد فعلی

| بخش | محل اصلی و رفتار مشاهده‌شده در سورس |
| --- | --- |
| فهرست گفتگو | `src/features/personal/messaging/messenger.tsx`؛ جستجو و فیلتر با پارامتر سرور، انتخاب گفتگو، منوی ایجاد گروه/کانال، مخاطبین، آرشیو و ذخیره‌شده |
| ظاهر فهرست و چت | `messenger.module.css`؛ چیدمان دو ستون از ۷۶۸px، تک‌صفحه‌ای زیر آن، ستون ۳۰۰/۳۲۰px، چند بلوک بازنویسی متوالی استایل از طراحی قبلی |
| نشان خوانده‌نشده | کلاس `.unread` عدد واقعی را در DOM نگه می‌دارد ولی ظاهر آن نقطهٔ ۷px و متن شفاف است؛ تطابق با badge مرجع باید در مرحلهٔ طراحی اصلاح شود |
| منوی ساخت | `.floating` در سربرگ به‌صورت fixed قرار دارد؛ جای دقیق آن بعد از دریافت تصویر مرجع تعیین می‌شود |
| اتاق گفتگو | `conversation-room.tsx`؛ هدر، تاریخچه، پاسخ، صف ارسال، خطا، وضعیت خواندن و کادر نوشتن؛ رفتار API نباید با بازطراحی حذف شود |
| رسانه | `media.tsx`، `media.module.css` و `media-model.ts`؛ انتخاب و پیش‌نمایش، بارگذاری، دریافت، خطا و تلاش مجدد؛ قرارداد و مجوز فایل مستقل از ظاهر است |
| زنده و نشست | `live.tsx`، `account-replay.ts` و `selection.tsx`؛ بازطراحی نباید جداسازی حساب/زمینه یا به‌روزرسانی فهرست گیرنده را مختل کند |

این جدول حاصل خواندن کد است، نه گزارش مشاهدهٔ رابط روی Docker یا اثبات عملکرد زندهٔ سرور.

## بررسی مستقل انجام‌شده

فرمان اجراشده از `web/`:

```powershell
npm test -- --run tests/unit/conversation-summary.test.ts tests/unit/messaging-hub-protocol.test.ts tests/unit/messaging-files.test.ts tests/unit/personal-conversation-policy.test.ts tests/unit/personal-message-queue.test.ts
```

نتیجه: **۲۸ تست موفق در ۵ فایل؛ صفر ناموفق**. خلاصه و ترتیب گفتگو، پروتکل پیام‌رسان، قواعد فایل، سیاست گفتگوی شخصی و صف پیام در محیط مستقل بررسی شدند. این نتیجه، آزمون تصویری، ارسال واقعی روی سرور یا تأیید امنیت بک‌اند نیست.

ساخت production موجود متعلق به ۳۰ اکتبر بود؛ به‌عنوان شاهد رابط سورس جاری استفاده نشد. build، آزمون مرورگر و استقرار جدید اجرا نشدند؛ کد runtime تغییر نکرد. تغییر قبلی `readme.md` کاربر حفظ شد.

## مراحل اجرایی پس از رفع مانع

۱. دریافت context و render صفحه‌های روشن/تاریک و منو/پیوست، شناسایی دارایی‌های قابل استفاده و ثبت مجوزها.
۲. بازطراحی فهرست، جستجو، badge عددی و انتخاب گفتگو؛ سپس هدر چت، حباب، زمان/خواندن، کادر نوشتن و پیوست، با حفظ سرویس‌ها و RTL.
۳. تطبیق تبلت/دسکتاپ با الگوی مرجع موبایل؛ فایل بررسی‌شده تاکنون به‌تنهایی شاهد طراحی دسکتاپ نیست.
۴. مقایسهٔ تصویری در ۳۹۰، ۸۳۴ و ۱۴۴۰ و عرض‌های مرزی؛ بررسی تمرکز، لمس، ارسال، دریافت، خطا و تغییر اندازه در fixture ایزوله.
۵. build و بررسی‌های پروژه؛ تحویل تصاویر واقعی و اعلام جداگانهٔ نتیجهٔ اتصال زنده و استقرار.
